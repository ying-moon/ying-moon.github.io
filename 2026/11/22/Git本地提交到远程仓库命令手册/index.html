场景：在本地改完代码（比如你的 Hexo 博客），把改动推送到远程仓库。

二、核心四步：本地 → 远程

这是每次提交都要走的完整流程，记住这四条就够用：

1. git status 看状态

输出里的颜色含义：

状态 含义
红色 modified 改了但还没 add
绿色 new file 新文件，已 add
Untracked files 新文件，Git 还没管过它

2. git add 加入暂存区

git add . 和 git add -A 的区别：.git 目录下（当前路径）的改动，-A 是整个仓库。日常在自己的项目根目录里操作，两者基本一样。

撤销误添加（文件还在，只是移出暂存区）：

3. git commit 提交到本地

提交信息怎么写好看：

常用类型：feat 新功能、fix 修 bug、style 样式、docs 文档、refactor 重构、chore 杂项。

单行简写也行：git commit -m "fix: 修正 flatpaper 二级菜单 children 写法"

4. git push 推送到远程

第一次推送新仓库，用 git push -u origin main。-u 是把本地分支和远程分支绑定，以后再 git push 就不用带参数。

六、撤销与回退（弄错了看这里）

已经推送到远程的提交，**不要用 reset --hard 再 push -f**，会破坏别人的仓库。用 git revert 生成一条反向提交更安全。

七、常见问题排查

git push 报 rejected / non-fast-forward

原因：远程有你本地没有的提交（比如在网页上改过文件）。

报 fatal: refusing to merge unrelated histories

两个仓库历史不相关，第一次合并时加参数：

报 Permission denied (publickey) 或要输密码

  • HTTPS 方式：GitHub 已不支持密码，要用 Personal Access Token（在 GitHub → Settings → Developer settings → Personal access tokens 生成，勾选 repo 权限），推送时把 token 当密码填。
  • SSH 方式：本机生成密钥后把公钥加到 GitHub。

八、一页速查表

目的 命令
看改了什么 git status / git diff
加入暂存区 git add .
提交本地 git commit -m "说明"
推送远程 git push
拉取远程 git pull
首次推送新分支 git push -u origin main
查看远程地址 git remote -v
撤销暂存 git restore --staged 文件
丢弃修改 git restore 文件
回退一次提交（保留改动） git reset --soft HEAD~1
安全撤销已推送提交 git revert 哈希 + git push
看历史 git log --oneline --graph
找回误删 git reflog
